AI Voice Slide Presenter

A browser talks directly to a speech-to-speech AI — Google's Gemini Live API — over a WebSocket. On Start it presents a hardcoded deck on its own, flips to the right slide when you ask a question, and can be interrupted mid-sentence. The backend does one small job: hand out a short-lived token.

The big picture

Two loops sharing one connection

Everything real happens in the browser. The audio path (teal) is a direct WebSocket between your mic/speaker and the Gemini Live API — the backend never touches your voice. The control path (violet) is the same WebSocket carrying a tool-call message: when the model decides to move the deck, it calls goto_slide() and React updates the slide.

The backend exists only to keep your secret API key off the browser. It mints a short-lived token, and then it's out of the way.

Startup

What happens when you click “Start”

The click matters for two reasons: browsers block audio until a real user gesture, and it's the moment to fetch a fresh token — Gemini tokens are short-lived (about a minute to connect), so you mint one then connect immediately. The browser opens a WebSocket session with the @google/genai SDK (ai.live.connect), and from that point audio flows on its own.

A normal turn

Speak → reason → (maybe change slide) → narrate

Most turns skip the violet branch entirely — the model just answers about the current slide. The interesting case is when your question belongs elsewhere: the model calls goto_slide() first so the deck is already showing the right slide by the time it starts talking, and then narrates. To pick the right slide it needs a table of contents of the deck in its instructions. The one thing to tune here is thrashing — telling it not to jump for small follow-ups about the slide you're already on.

Presentation mode

How it presents on its own

Click Start and the app does not wait to be asked. It sends the model one nudge to begin, and from there the model runs the show: a short greeting and intro, then each slide in turn — it calls goto_slide() first, narrates for a minute or two, and ends with "any questions?". Ask something and it answers, then asks "anything else?"; stay silent and it moves on.

The model has no clock, though, so the app owns the pacing. After every turn it starts an 8-second timer (PROCEED_WAIT_MS); if you speak, the timer is cancelled and you are answered; if it runs out, the app tells the model "no questions — continue," and it advances. Saying "no, go ahead" advances immediately. On the last slide it wraps up instead of advancing.

Barge-in

What has to happen the instant you interrupt

While the model talks, audio streams ahead of what you're hearing and piles up in a playback buffer. Gemini's voice-activity detection notices you talking and stops generating — but that buffer will keep playing on its own. So when the interrupted event arrives, the client actively stops playback and throws away the queued audio. Gemini's session already tracks what you actually heard, so it does not need a separate cancel.

Skip the flush and the buffer keeps playing after you've interrupted — so what you hear no longer matches where the model actually stopped. This is the number-one reason voice demos feel broken.

Glossary

Terms in one line each

WebSocketA persistent two-way connection the browser holds open to stream audio and receive events, including tool calls.
Live sessionThe open, stateful WebSocket conversation with Gemini; it remembers the dialogue for the whole session.
Ephemeral tokenA short-lived credential the browser uses instead of the real API key. Mint it, connect fast.
VADVoice activity detection — the server noticing when you start and stop speaking.
Barge-inInterrupting the AI mid-sentence and having it actually stop.
FlushEmptying the playback buffer so no already-queued audio keeps playing after an interrupt.
Function callingThe model choosing to invoke a defined tool (goto_slide) instead of only speaking.
System instructionThe standing brief — persona plus the deck's table of contents — the model follows all session.
